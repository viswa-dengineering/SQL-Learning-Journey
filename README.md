# SQL Learning Journey

This repository documents my **SQL learning journey through hands-on practice and problem-solving**.

Rather than only learning SQL syntax and concepts theoretically, this repository focuses on understanding **how business questions can be converted into SQL queries**.

Each practice section demonstrates my learning process:

```text
BUSINESS QUESTION
       ↓
UNDERSTAND THE DATA
       ↓
IDENTIFY THE SQL PATTERN
       ↓
WRITE THE QUERY
       ↓
TEST THE RESULT
       ↓
IDENTIFY MISTAKES
       ↓
DEBUG AND CORRECT
       ↓
DOCUMENT THE LEARNING
```

## 🎯 Repository Objective

The objective of this repository is to build practical SQL problem-solving skills required for working with data.

My focus is not only on learning commands such as:

```text
SELECT
WHERE
GROUP BY
HAVING
JOIN
SUBQUERY
WINDOW FUNCTIONS
```

but also understanding:

* What business question needs to be answered.
* What data is available.
* Which tables and columns are required.
* How the data should be filtered.
* When data should be grouped and aggregated.
* When multiple tables need to be joined.
* Which SQL pattern is appropriate for the problem.
* How to debug incorrect queries.
* How to improve SQL problem-solving skills through repeated practice.

# 🔍 Example of My Practice Method

A business question might be:

> Find employees earning more than the company's average salary.

My approach is:

```text
Business Question
       ↓
What information do I need?

Employee Salary
       +
Company Average Salary
       ↓
Company average is ONE calculated value
       ↓
Use a Single-Row Subquery
       ↓
Compare every employee salary
with the company average
```

The SQL pattern becomes:

```text
OUTER ROW VALUE
      >
ONE VALUE FROM SUBQUERY
```

This method helps me focus on the **logic behind the query**, rather than memorizing SQL syntax.

# 🐛 Learning From Mistakes

An important part of this repository is documenting mistakes.

During SQL practice, I may:

* Choose the wrong column.
* Use an incorrect SQL operator.
* Write an incorrect `JOIN` condition.
* Use `WHERE` when `HAVING` is required.
* Return multiple values from a Single-Row Subquery.
* Place calculations in the wrong query level.
* Misunderstand aggregation logic.

Instead of deleting these mistakes, I analyze them and document:

```text
INCORRECT QUERY
       ↓
WHY IT FAILED
       ↓
WHAT SQL LOGIC WAS MISSING
       ↓
CORRECT QUERY
       ↓
LESSON LEARNED
```

This helps me improve my SQL debugging and problem-solving ability.
